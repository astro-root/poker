# デザイン刷新前の課題

確認日: 2026-10-19

`docs/design/before/` に `/`、`/ai`、`/online`、`/terms`、`/hands` の全5ルートを、360×640、390×844、768×1024、1280×800、1920×1080、844×390 の6ビューポートで保存した（計30枚）。

## 目視で確認した課題

1. **文字が小さい**: 補助説明やラベルの多くが8〜11px。スマートフォンでは卓上の役・チップ・アクション補助が読みづらく、本文の基準16pxにも達していない。
2. **卓の情報が重なる**: AI卓の勝率推定テキストが共通カードの領域に重なる。特に360×640で文字がカード裏面にかかり、読み取りづらい。
3. **モバイルの卓が窮屈**: 360×640では相手席が複数段に並び、卓の楕円と共通カードの空間が小さい。自分の手札や卓下端も近接し、重要情報の優先順位が伝わりにくい。
4. **固定高とクリップ**: `.game-panel` と `.felt` が `overflow: hidden`、`.play-layout` が viewport 高さを基準に固定されている。短い画面では卓が圧縮され、内容追加時に切れる可能性がある。アクション領域は別途最大高と内部スクロールを持つ。
5. **操作領域の密度**: レイズスライダー、プリセット、主要アクションが同じ領域に詰まり、モバイル時にタップしづらい。アクション領域を画面下に固定する構造ではない。
6. **配色と枠の古さ**: 明るい背景、茶色の太い卓枠、強い段付き影が画面全体を占め、指定の落ち着いたダーク基調から離れている。
7. **視覚状態の差分が未撮影**: 30枚は各ページの初期表示。AI卓のレイズ操作中、ショーダウン結果、相手の手番を個別状態として固定した画像は未取得。オンラインはロビー初期表示であり、参加中・対戦中・終局の実データ状態も未取得。

## 自動確認の制限

Playwright の撮影スクリプトはページ初期表示の画像を記録する。オンライン参加状態は Supabase の実環境を使うため、このベースラインでは再現していない。レイアウト項目は画像を目視しながら追加確認する。

## after の確認状況

`docs/design/after/` に同じ5ルート × 6ビューポートの30枚を保存した。初期表示の計測では横スクロールと12px未満の文字は解消した。モバイルのアクション操作領域は卓の下に置き、卓や手札に重ならないことを優先した。

次の項目はまだ残っている。

- 主要3〜6人の席を楕円卓の周囲へ配置するデスクトップ用レイアウト。
- スマートフォンで手札とアクションを画面下に固定するレイアウト。現在は操作領域が卓の下に続く。
- レイズ中、ショーダウン、相手の手番、オンライン参加中・対戦中・終局の状態別スクリーンショット。
- `test/e2e/*.spec.ts` と `npm run test:e2e` によるスモークテスト。
- 色の直書きの CSS トークンへの置換と、全画面・全状態でのコントラスト確認。
