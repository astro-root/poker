# ポーカー

無料で遊べるオンライン・テキサスホールデムサービスを開発しています。開始時点のリポジトリには `develop-prompt.md` 以外のアプリ、フレームワーク、テスト、デプロイ設定はありませんでした。

## 現在の実装

- 52枚のカードデッキ、暗号学的乱数によるシャッフル
- 5〜7枚からの役判定と同役時の比較
- メインポット／サイドポットの組み立てと端数チップ分配
- ブラインド、チェック、コール、ベット、レイズ、短いオールイン、フォールドを扱うベッティングラウンド
- ヘッズアップ／複数人のブラインド配置、配札、プリフロップからリバーまでの進行
- ショーダウン時に各ポットの対象者から勝者を選び、チップを分配
- 全員オールイン時の自動ランアウトと、全員フォールド時の即時決着
- クライアント向け状態生成時に、相手の手札と未配札デッキを除外
- テーブル上のチップ残高、複数ハンド間のボタン移動、空席のスキップ
- テーブル状態バージョンによる古いアクションの拒否
- 推測困難なゲストセッションと、トークンのハッシュ照合
- 招待URLで参加する2〜6人のオンライン対戦（Supabase Edge Function が配札・アクション・チップを管理）
- 合法アクションと自分の手札／公開カードだけを使い、プレイ傾向と残っている相手人数を考慮するルールベースAI
- 現在の役の理由と14項目の日本語ポーカー用語集

ひとり練習は端末内で進行します。招待対戦の全手札・山札・正規のゲーム状態は Supabase Edge Function と非公開DBテーブルだけで管理します。参加者には自分の手札と公開情報だけを返します。ルーム作成、招待URLの共有、匿名ゲスト参加で遊べます。ゲームチップに金銭価値はありません。

## 技術方針

### Vercel とオンライン基盤

画面は Vite の静的サイトとして Vercel に配置し、オンライン対戦は Supabase Edge Function と Postgres を使います。DBの全状態を読めるのはサーバー関数だけです。関数は呼び出しユーザーに合わせて手札を伏せ、アクションを検証してからバージョン比較付きで状態を保存します。ブラウザー側のホストも相手の手札や未配札デッキを受け取りません。

ルーム更新は画面から1.5秒ごとに取得し、状態はDBの比較更新で競合を拒否します。Supabase側で必要な準備は[セットアップ手順](SUPABASE_SETUP.md)にまとめています。

無料枠には上限があり、内容は変更されることがあります。公開前に[Supabaseの料金と上限](https://supabase.com/pricing)を再確認します。

Vercel Functions の WebSocket も利用可能になっていますが、Function の実行時間で接続が終了し、再接続先が別インスタンスになることがあります。Supabase Realtime を採用する場合、アプリ独自の WebSocket サーバーはまず作らず、Vercel Functions は短いリクエスト処理に使います。[Vercel の WebSocket ガイド](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)

### ライブラリ

画面は Vite と TypeScript で構成し、Supabase Auth に公式 JavaScript クライアントを使います。ブラウザーでは Web Crypto、テストやサーバー側処理では Node.js の標準機能を使います。ポーカー判定やUIコンポーネント用の外部ライブラリは追加していません。

Node.js の対応バージョンは `package.json` の `engines` を参照してください（現在は 22.12 以降）。

## ブラウザー練習画面

対戦相手のAIは1人・3人・5人から選択でき、選択は端末内に保存します。人数を変えると新しいハンドで練習を再開します。各席のスタック残量をバーで比較でき、ベット額は最小・1/2ポット・ポットのプリセットから選べます。

`index.html` と Vite で動く日本語の練習画面です。対戦人数は1・3・5人から選べ、異なるスタイルのAIとプレイできます。ハンドごとにボタンが移動し、10ハンドごとにブラインドが上がります。各判断でランダムな相手の手札を使った勝率のモンテカルロ推定を表示し、希望時にはポットオッズと照らしたコーチの助言を確認できます。初回向けルール案内、アクション履歴、現在の役の説明、ベットサイズのプリセットもあります。プレイヤー名と直近10ハンドのリプレイ用記録は端末内に保存し、勝敗とチップ増減を集計します。ショーダウンでは公開された手札と役、メイン／サイドポットごとの獲得者を表示します。画面は広いテーブル表示からスマートフォンの縦画面まで対応します。ルールコアはサーバー専用APIに依存せず、ブラウザーでも使えるWeb Cryptoでデッキをシャッフルします。

この画面は **端末内だけの練習デモ** です。プレイヤー名はブラウザーの localStorage に保存します。状態とAIの手札もブラウザー内にあるため、オンライン対戦や不正防止を提供するものではありません。友人用URL、公開ルーム、再接続を実際に提供するには、別途サーバーAPIと永続化が必要です。

Vercel では Vite プロジェクトとしてビルドコマンド `npm run build`、出力先 `dist` を使います。

## コマンド

- `npm run dev` — ローカル開発サーバーを起動
- `npm run build` — Vercel向け静的ファイルを生成
- `npm run preview` — 生成物をローカル確認
- `npm test` — ルールコアのテストを実行
- `npm run typecheck` — 開発依存をインストールした状態で型を確認

## Supabase Auth のローカル設定

Supabase Dashboard で Anonymous Sign-Ins を有効にし、`.env.example` を `.env.local` にコピーして次の値を設定します。

- `VITE_SUPABASE_URL` — Project URL
- `VITE_SUPABASE_PUBLISHABLE_KEY` — Publishable key

値を設定した後 `npm run dev` を再起動すると匿名ゲストIDを取得します。どちらかの値が未設定ならローカル練習モードで動きます。Secret key はブラウザー変数に設定しないでください。Vercelで試す場合は同じ2つをProject Settings → Environment Variablesに登録して再デプロイします。

招待対戦では Supabase CLI でDBマイグレーションを適用し、`rooms` Edge Function をデプロイします。ホストが切断してもDBのルーム状態は残り、同じゲストセッションで再接続すると復元できます。

## ゲストとルームのセキュリティ

ゲストセッションは推測困難なトークンを一度だけ発行し、サーバー状態にはトークンの SHA-256 検証値を保存します。実際のWeb/API層を追加するときは、トークンを `HttpOnly`, `Secure`, `SameSite` Cookie で扱い、URLやログに出さないでください。招待URLに含めるのは認証情報ではなくルームIDだけです。

ルームとテーブルの現在の関数は、検証可能な状態遷移ロジックです。プロセス内メモリへの保存やルーム一覧の永続化はしていません。Vercel へ接続する段階では Supabase Postgres のトランザクションでルーム状態を更新し、`version` を比較して同時操作を直列化します。再接続時はゲストセッションを検証したあとにDBから状態を再取得します。Supabase Realtime へ送るのは公開用状態だけにします。

## 現在の制約

オンライン対戦は現金価値のないチップのみです。テーブル作成時はチップのないプレイヤーも座席順を維持し、ハンド開始時にはチップのあるプレイヤーのみ参加します。サーバー専用の `PokerHand` は未配札デッキと全員の手札を含むため、Edge Function は自分以外の手札とデッキを応答から除外します。DBテーブルはRLSを有効にし、`anon` と `authenticated` からの直接アクセスを拒否します。アクションごとにDBリビジョンとテーブルバージョンを比較し、古い同時操作を拒否します。奇数チップはディーラーボタンの次から時計回りに配分します。
