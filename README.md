# ポーカー

無料で遊べるオンライン・テキサスホールデムサービスを開発しています。開始時点のリポジトリには `develop-prompt.md` 以外のアプリ、フレームワーク、テスト、デプロイ設定はありませんでした。

## 現在の実装

- 52枚のカードデッキ、暗号学的乱数によるシャッフル
- 5〜7枚からの役判定と同役時の比較
- メインポット／サイドポットの組み立てと端数チップ分配
- ブラインド、チェック、コール、ベット、レイズ、短いオールイン、フォールドを扱うベッティングラウンド
- ヘッズアップ／複数人のブラインド配置、配札、プリフロップからリバーまでの進行
- ショーダウン時に各ポットの対象者から勝者を選び、チップを分配
- 全員オールイン時の自動ランアウトと、全員フォールド時の即時決着
- クライアント向け状態生成時に、相手の手札と未配札デッキを除外
- テーブル上のチップ残高、複数ハンド間のボタン移動、空席のスキップ
- テーブル状態バージョンによる古いアクションの拒否
- 推測困難なゲストセッションと、トークンのハッシュ照合
- 招待ルーム／公開ルーム、定員、観戦参加、ホスト移譲、再接続状態
- 合法アクションと自分の手札／公開カードだけを使うルールベースAI
- 現在の役の理由と14項目の日本語ポーカー用語集

ゲーム状態と勝敗の決定はサーバー側を正とします。

## 技術方針

### Vercel とオンライン基盤

現在の画面は Vite の静的サイトとして Vercel にデプロイできます。オンライン機能を実装する段階では、Vercel Functions などにサーバーAPIを追加する設計が必要です。データベース・リアルタイム通信には Supabase を候補として調査しましたが、接続実装はまだありません。

対戦アクションは Vercel のサーバーAPIで検証し、Postgres のトランザクション内でルーム状態とバージョンを更新する設計にします。クライアントから届いたカード、残高、勝敗は信用しません。Realtime は更新通知に使い、クライアント同士でゲーム状態を直接決めさせません。非公開手札は権限を持つ本人にだけ返し、観戦者向け・ルーム全体向けの配信データから除きます。再接続後はDBの最新状態を取り直します。

Supabase Realtime はチャンネル単位の Broadcast と Presence を提供します。Presence はオンライン表示など低頻度の状態に使い、ゲーム中の手札や権威あるゲーム状態の保存には使いません。[Realtime の仕組み](https://supabase.com/docs/guides/realtime/architecture) と[認可設定](https://supabase.com/docs/guides/realtime/authorization)を確認し、チャンネルとDBの権限を設計します。

無料枠には上限があります。現行の公式表では Free プランの Realtime は同時接続200、毎秒100メッセージが上限として示されています。公開前に最新のプラン上限と利用量を再確認します。[Supabase Realtime の上限](https://supabase.com/docs/guides/realtime/limits)

Vercel Functions の WebSocket も利用可能になっていますが、Function の実行時間で接続が終了し、再接続先が別インスタンスになることがあります。Supabase Realtime を採用する場合、アプリ独自の WebSocket サーバーはまず作らず、Vercel Functions は短いリクエスト処理に使います。[Vercel の WebSocket ガイド](https://vercel.com/kb/guide/do-vercel-serverless-functions-support-websocket-connections)

### ライブラリ

ポーカールールコアの実行時依存は現在ありません。Node.js 標準の `crypto` とテストランナーを使っています。TypeScript と `@types/node` は開発用です。画面の実装時には Next.js と React、Supabase 接続時には Supabase の公式 JavaScript クライアントを追加する予定です。現段階ではポーカー判定やUIコンポーネント用の外部ライブラリは追加しません。

現在のテスト実行には Node.js 22.6 以降が必要です。

## ブラウザー練習画面

`index.html` と Vite で動く日本語の練習画面を追加しました。PCとスマートフォンでテーブル、手札、共通カード、ポット、アクション、現在の役の説明を確認でき、AIとハンドを最後まで進められます。初回向けルール案内と現在選べる操作の説明があります。ベットに直面したときは、引き分けや将来のベットを考慮しない単純なコール損益分岐の勝率目安（ポットオッズ）を表示します。プレイヤー名を保存でき、ハンド中のアクション履歴を振り返れます。終了した直近10ハンドのアクション・公開ボード・結果要約を端末内に保存し、勝敗とチップ増減を集計します。ショーダウンでは公開された手札と役、メイン／サイドポットごとの獲得者を表示します。ルールコアはサーバー専用APIに依存せず、ブラウザーでも使えるWeb Cryptoでデッキをシャッフルします。

この画面は **端末内だけの練習デモ** です。プレイヤー名はブラウザーの localStorage に保存します。状態とAIの手札もブラウザー内にあるため、オンライン対戦や不正防止を提供するものではありません。友人用URL、公開ルーム、再接続を実際に提供するには、別途サーバーAPIと永続化が必要です。

Vercel では Vite プロジェクトとしてビルドコマンド `npm run build`、出力先 `dist` を使います。

## コマンド

- `npm run dev` — ローカル開発サーバーを起動
- `npm run build` — Vercel向け静的ファイルを生成
- `npm run preview` — 生成物をローカル確認
- `npm test` — ルールコアのテストを実行
- `npm run typecheck` — 開発依存をインストールした状態で型を確認

## ゲストとルームのセキュリティ

ゲストセッションは推測困難なトークンを一度だけ発行し、サーバー状態にはトークンの SHA-256 検証値を保存します。実際のWeb/API層を追加するときは、トークンを `HttpOnly`, `Secure`, `SameSite` Cookie で扱い、URLやログに出さないでください。招待URLに含めるのは認証情報ではなくルームIDだけです。

ルームとテーブルの現在の関数は、検証可能な状態遷移ロジックです。プロセス内メモリへの保存やルーム一覧の永続化はしていません。Vercel へ接続する段階では Supabase Postgres のトランザクションでルーム状態を更新し、`version` を比較して同時操作を直列化します。再接続時はゲストセッションを検証したあとにDBから状態を再取得します。Supabase Realtime へ送るのは公開用状態だけにします。

## 現在の制約

まだ遊べるオンラインサービスではありません。Supabaseとの接続、HTTP API、招待・公開ルーム画面、オンライン同期、観戦・戦績は未実装です。AI対戦と学習用UIはブラウザー内の練習機能として実装済みですが、サーバー権威のAIではありません。ルーム関数は状態遷移ロジックであり、サーバー認証やDBの排他制御を代替しません。テーブル作成時はチップのないプレイヤーも座席順を維持し、ハンド開始時にはチップのあるプレイヤーのみ参加します。サーバー専用の `PokerHand` は未配札デッキと全員の手札を含むため、そのままクライアントへシリアライズせず、`getPublicHandView` または `getPublicTableView` を使ってください。アクションごとにテーブルバージョンが進み、古いバージョンのアクションは拒否されます。奇数チップはディーラーボタンの次から時計回りに配分します。
